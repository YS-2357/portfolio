# ✨ Info

- **프로젝트명**: AI 개발 하니스 엔지니어링 (멀티 에이전트 SSOT)
- **기간**: 2026.05 ~ 진행 중
- **형태**: 개인 사이드 프로젝트
- **자료**: 비공개 저장소 (요청 시 시연 가능)

# 🔹 S (Situation) — 배경

> Claude Code·Codex·Kiro 등 AI 코딩 에이전트를 함께 쓰면 설정·규칙·스킬이 도구마다 흩어지고, 같은 원칙이 서로 다르게 복제되어 금방 어긋납니다.
>
> 에이전트가 늘어날수록 관리 비용이 커지는 문제를 **단일 진실 공급원(SSOT)** 으로 풀기로 했습니다.

---

# 🔹 T (Task) — 목표와 과제

> 모든 에이전트의 공용 원칙·스킬·런타임 설정을 한 저장소에서 관리하고, 한 번의 적용 명령으로 각 도구의 네이티브 설정에 배포되는 구조를 만드는 것.
>
> 품질 판단은 모델의 자기평가가 아니라 **결정적 검증(테스트·린터·렌더러)** 이 담당하도록 설계.

---

# 🔹 A (Action) — 수행 작업

## 🧭 SSOT 구조

- 공용 코딩 원칙·위임 규칙을 단일 저장소에서 관리, apply 스크립트로 각 에이전트 설정에 동기화
- 모델 라우팅 정책(작업 유형 → 모델 티어)을 JSON SSOT로 정의하고 훅으로 강제
- 크로스 모델 협업 규칙(교차 리뷰·구조 진단)을 스킬로 명문화 — 서로 다른 모델의 블라인드스팟 상호 보완

## 🛠️ 스킬 시스템

- 문서 생성·검증 스킬: 리포트/가이드/슬라이드를 스크립트가 조립·렌더·검증 (모델은 내용만 담당)
- 클라우드 아키텍처 다이어그램 스킬: JSON 명세 → draw.io 렌더링 + 교차선 린트
- 로컬 LLM 연동 스킬: 머신별 가용 모델 탐지, 오프라인·프라이버시 작업 위임 규칙

## ✅ 검증·자동화

- 스킬 검증기 단위 테스트, 설정 불변식(invariant) 테스트
- launchd 기반 **주간 report-only 자기개선 파이프라인** — 하니스가 자기 상태를 점검·보고
- "실패는 시끄럽게, 성공은 조용히" 원칙: 침묵 폴백 금지, 결정적 게이트 통과 없이는 완료 선언 금지

---

# 🔹 R (Result) — 결과

- 에이전트 3종이 같은 원칙·같은 스킬로 동작 — 설정 드리프트 제거
- 검증 게이트 도입 후 "모델이 됐다고 말하는 것"과 "실제로 되는 것"의 간극을 커맨드가 판정
- 문서·다이어그램·리뷰 등 반복 작업이 스킬 호출 1회로 표준화

# 📌 회고 (Reflection)

- AI 에이전트 시대의 생산성은 프롬프트가 아니라 **하니스(검증·라우팅·규칙의 구조)** 에서 나온다는 확신을 얻었습니다.
- 모델 티어보다 결정적 검증이 품질을 결정합니다 — 같은 모델도 게이트가 있으면 결과물이 달라집니다.
- 진행형 프로젝트로, 스킬·검증기를 계속 추가하며 운영 중입니다.
